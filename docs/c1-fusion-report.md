# C1 可见光 / 红外融合对照报告（第一轮）

> 一句话结论：**这一轮的融合对照不成立**。RGB 单模态 mAP50 = 0.7002，融合后 0.6457（−0.0545），
> 红外单模态在 RGB 像平面上只有 0.1593。根因不是"情报不够"，而是 **IR→RGB 的几何映射精度不够**：
> 相似变换的残差 p90 达 579 px，误差集中在远处小目标上，把红外检测框搬到了错误位置。
> 另外得到一个**正面结果**：红外在自己的像平面上、640 分辨率下 mAP50 = 0.7674，高于可见光 1280 分辨率的 0.7027。

## 1. 实验设置

| 项 | 设置 |
|---|---|
| 数据 | OSDaR23，18 个序列，rgb_center 与 ir_center 各 516 帧（提示：只有 1_calibration 与 4.3/4.4/4.5 是长序列） |
| 验证集 | 同一批 155 帧，两路各自用自己相机上的标注评分 |
| 类别 | 0 buffer_stop / 1 catenary_pole / 2 person / 3 road_vehicle / 4 signal_pole（两路一致） |
| RGB 模型 | `runs/detect/osdar23-yolov8n-516img-1280/weights/best.pt`，推理 imgsz 1280 |
| 红外模型 | `runs/detect/osdar23-yolov8n-ir/weights/best.pt`，推理 imgsz 640 |
| 评测器 | 自写 `railintrude.evaluate`（COCO 101 点插值），与 ultralytics 的 val 口径一致 |
| 映射拟合 | 相似变换（4 自由度，RANSAC），**只用 train 划分的 538 对同类 GT 中心** |
| 融合规则 | 以 RGB 为主、IR 补盲：IR 框映射后与同类 RGB 框中心距 ≤ 40 px 视为重复 |

## 2. 三路结果（155 帧）

| 臂 | mAP50 | mAP50-95 | 大暗区子集 mAP50（131 帧） |
|---|---|---|---|
| rgb_only | **0.7002** | **0.4409** | **0.7101** |
| ir_only（映射到 RGB 平面评分） | 0.1593 | 0.0827 | 0.1569 |
| fusion（RGB 主 + IR 补盲） | 0.6457 | 0.4087 | 0.6573 |

对照：同一批权重用 ultralytics 原生 val（各自像平面）得到 **RGB 0.7027 / IR 0.7674**。
rgb_only 的 0.7002 与之吻合，说明**自写评测器是正确的**（这是这轮最有价值的副产品）。

## 3. 每类发生了什么（诊断关键）

| 类别 | rgb_only AP50 | fusion AP50 | ir_only AP50 |
|---|---|---|---|
| buffer_stop | 0.8310 | 0.8431 | **0.7236** |
| catenary_pole | 0.5355 | 0.5040 | 0.0592 |
| person | 0.7112 | 0.5770 | 0.0093 |
| road_vehicle | 0.9524 | 0.9068 | 0.0037 |
| signal_pole | 0.4708 | 0.3974 | 0.0007 |

红外臂只有 buffer_stop 活下来（0.7236），其余四类几乎归零。
buffer_stop 是"近处、大框"的目标，person / road_vehicle / signal_pole 是"远处、小框"——
**误差随距离增长**，这不是类别问题，是几何问题。

## 4. 根因：4 自由度相似变换表达不了两个相机的视差

- 拟合出的 A = [[1.2827, 0.0005, 850.417], [−0.0005, 1.2827, 734.798]]，尺度与内参比 4609.47/3535.29 = 1.30384 相差 1.6%，旋转仅 0.02°（近似平行光轴）。
- 但残差分布极偏：**中位 18.8 px、均值 123.5、p90 579.4、最大 637.6**（RGB 图宽 2464）。
- 原因：相似变换只对"与像平面平行的平面"严格成立。IR 相机在 Z≈3.52 m、Y=+0.2527 m，RGB 在 Z≈3.50 m、Y=−0.2859 m，
  横向错开 0.54 m、光心 cy 也不同（239.5 vs 820.05）。同一映射在近处和远处需要的平移量不同，
  统一平移必然在某一端失准 —— 而 AP 对远处小目标的错位最敏感。
- 结论：**融合的瓶颈是配准，不是检测器**。在配准精度没有数量级改善之前，任何"再融合一次"的调参都不会有正收益。

## 5. 正面结果：红外本身是强模态

红外在自己的像平面上（640，原生分辨率）mAP50 = **0.7674**、mAP50-95 = 0.5053，
其中 signal_pole 的 mAP50-95 达 **0.6825**，比可见光 1280 的 0.476 高出 0.2 以上。

这支持"红外在弱光下有用"的动机，但注意两点，答辩时不能含混：
1. 该数字是红外图像 640×480 **原生分辨率**下的成绩，与可见光 1280 不同分辨率，不是同条件对照；
2. 它没有解决"两种模态怎么合起来用"的问题——这正是本轮失败的部分。

## 6. 诚实的局限

- 融合只试了"框级晚融合 + 一个相似变换"这一种实现，**没有**试标定驱动的相机模型投影、也没有用 LiDAR 深度。
- 验证集 155 帧、单次训练、无多种子重复；暗区子集 131/155，与全集高度重合（这个数据集本身 85% 的帧都偏暗），
  所以"暗区 0.7101 vs 全集 0.7002"说明不了弱光鲁棒性——**该数据集不足以支撑"夜间"这一主张**。
- 配对用的是"同类按中心 x 排序一一配对"的启发式，本身会引入错配（这正是 RANSAC 内点率只有 43.9% 的原因）。

## 7. 下一步（按性价比排序）

1. **用官方标定做真正的投影**：`calibration.txt` 给了每个相机的内参与到车体坐标系的 4×4 齐次变换，
   配合 LiDAR 点云给每个目标的深度，把 IR 框投影到 RGB（而不是拟合一个全局矩阵）。
   这是把 0.16 拉回 0.7 量级的唯一正当路径。
2. **放弃像素级融合，改对象级关联**：两路各自在自己的平面上检测与评分，只做"同一目标"的关联与置信度融合，
   指标改为事件级（检出/漏检/误报），不再要求框位置一致。
3. 若目标是答辩材料而非新结论：**把红外作为"独立第二路报警"叙事**（双路冗余、任一触发即报警），
   这是工程上站得住、且不需要配准精度的方案。

## 9. 第二轮：标定驱动的投影（失败，但排除了一个方向）

按第 7 节第 1 条，实现了 `parse_calibration` / `project_ground` / `ground_homography`
（`railintrude/fusion.py`，有单测），用 `calibration.txt` 的内参与 4×4 齐次变换直接算
「轨面上一个点从 IR 像平面到 RGB 像平面的映射」，不拟合任何东西。结果全部失败：

| 做法 | 残差中位 | ≤20 px 占比 |
|---|---|---|
| 标定投影，四种约定各试一遍（最佳） | **72.1 px** | 0.0% |
| 只用「每帧该类唯一」的 31 对无歧义配对（最佳） | **100.8 px** | 0.0% |
| 同一批无歧义配对上的经验相似变换 | **4.1 px** | — |

- 标定投影的四种约定（`T` 是相机→车体还是车体→相机 × 光轴取 `+x/−y/−z` 还是 `+x/+y/+z`）都不行，
  最差 486 px、最好 72 px。**约定不该靠猜，但四种都不是**——更可能是 GT 框底边不等于轨面接触点。
- 决定性证据在最后一行：同样这 31 对无歧义配对，经验拟合只要 4.1 px，但拟合出的尺度是 **0.6265**；
  而用全部 538 对拟合出的尺度是 **1.2827**。同一对相机、同一批数据，尺度差 2 倍 →
  **2D bbox 的底边中点不足以唯一确定 IR↔RGB 关联**：杆状目标（catenary_pole / signal_pole）立在轨面旁边、
  底部常被截断或落在道砟上，行人站在站台面上（高度≠轨面），它们都不是「轨面上的点」。
- 结论：**这条路的失败不在代码，在于"轨面单应"这个假设本身**。要修必须引入 LiDAR 深度做真正的三维投影，
  成本远高于本项目剩余价值。

## 10. 第三轮：帧级融合（绕开配准，本轮的最终答案）

既然像素配准不可靠，就换一个问题：**同一帧里有没有某类目标**。RGB 与 IR 各自回答，按规则合并，
指标也是帧级的（漏检率 / 误报率 / F1）。这条路不需要任何配准，因此不受第 4、9 节的失败影响。

工具 `tools/eval_frame_fusion.py`，指标函数 `railintrude.evaluate.evaluate_presence`（4 个单测）。
设置：同一批 155 帧验证集，RGB 模型 imgsz 1280 / IR 模型 imgsz 640，conf 0.25，暗区判据 RGB 灰度值 <40 的像素占比 ≥30%。

| 分组 | 臂 | Precision | Recall | F1 | tp / fp / fn |
|---|---|---|---|---|---|
| 全集 155 帧 | rgb_only | 0.998 | 0.952 | **0.975** | 517 / 1 / 26 |
| 全集 | ir_only | 1.000 | 0.742 | 0.852 | 403 / 0 / 140 |
| 全集 | fusion_or | 0.998 | 0.952 | 0.975 | 517 / 1 / 26 |
| 全集 | fusion_and | 1.000 | 0.742 | 0.852 | 403 / 0 / 140 |
| 暗区 131 帧 | rgb_only | 1.000 | 0.943 | 0.971 | 430 / 0 / 26 |
| 暗区 | ir_only | 1.000 | 0.811 | 0.896 | 370 / 0 / 86 |
| 亮区 24 帧 | rgb_only | 0.989 | 1.000 | 0.994 | 87 / 1 / 0 |
| 亮区 | ir_only | 1.000 | 0.379 | 0.550 | 33 / 0 / 54 |

**这张表要这样读**：

1. `fusion_or` 与 `rgb_only` **逐格相同**（517/1/26）——即红外没有在任何一帧上补到可见光漏掉的目标。
   这是"红外没用"吗？不是。是**这个数据集上可见光已经足够**：131/155 帧偏暗，但 RGB 的 recall 仍有 0.943。
2. `fusion_and` 与 `ir_only` 相同，因为交集的召回被红外限制住，说明 IR 更适合当"补充证据"而不是"主判据"。
3. 红外在暗区 recall 0.811、亮区只有 0.379（相对自己的全集表现），**方向与物理直觉一致**：
   它确实更依赖热辐射对比。但绝对水平仍低于 RGB。
4. 那 26 个 RGB 漏检帧，红外也全漏了。**所以"红外能在可见光失效时救回来"这个说法，在这份数据上不成立。**

## 11. 三轮之后，C1 应该怎么写进答辩

诚实且站得住的写法：

- **不要**写"融合使 mAP 从 0.70 提到 X"——三轮实验里没有出现过正收益，编不出来。
- **可以**写"我们系统验证了可见光—红外融合在真实铁路数据上的三种技术路线（框级晚融合 / 标定投影 / 帧级决策融合），
  并定位出融合失效的根因是**跨模态配准精度**，而非检测器性能"——这是有数据支撑的工程结论，且是**负面结论**，
  评审无法用"你涨点了吗"击穿它。
- **可以**把红外定位为**冗余第二路**（双路各自报警，任一触发即报警），这是工程实践中的真实形态，
  不需要配准精度，也不需要 mAP 收益。
- 若答辩必须给一个正数：唯一有据的是"红外在自己的像平面上、640 分辨率下 mAP50 = 0.7674"，
  必须同时说明这不是同条件对照（与 RGB 1280 不同分辨率）。

## 13. 第三轮：用激光雷达真深度做逐目标关联（失败，但拿到了一个真能力）

前面两轮都是在二维平面上找 IR→RGB 的映射，前提是"目标的像点落在一个平面上"，这被证明不成立。
这一轮换前提：用激光雷达给每个目标一个**真实的米级深度**，再经标定把它推到三维、投到另一台相机。

### 13.1 先解决了一件事：点云到图像的外参链路是对的

`calibration.txt` 里每台相机给的是 4×4 齐次变换矩阵，但**没有写明方向**。穷举两种方向后，用图像判定：

- `p_parent = T @ p_lidar` 之后再做 `p_opt = (-y, -z, x)`（把 x前/y左/z上 转成 x右/y下/z前），
  点云精确落在站台边缘白线、栏杆、建筑立面上 —— **正确**；
- 反过来用 `T⁻¹` 再翻转，点云整体偏到画面左侧、站台边缘线消失 —— **错误**。

结论：`camera_from_calibration(T) = inv(T)`，共 4 个坐标变换函数已进 `railintrude/lidar.py`（8 个单测）。
这本身是个可用的能力：**给任意像素一个有物理含义的米级深度**，不再依赖 `d = a/(y − y_h)` 这种手调假设。

### 13.2 逐目标关联仍然失败，原因不是投影而是"框 → 深度"这一步

做法：取 IR 框底边中点，在该框下部一条带（高度 15%）里找落在框内的点云，用其中某个统计量当深度，
再把这个像素按该深度反投影成三维点、投到 RGB 像面，看它是否落在同类目标的 RGB 框内（容差 40 px）。

990 个 IR 框实测（4 个短序列）：

| 深度取值 | 命中同类 RGB 框 | 残差中位 | p25 | p75 |
|---|---|---|---|---|
| 最近点 | 0/990（0.0%） | 352.4 px | 260.9 | 408.6 |
| 1/4 分位 | 0/990（0.0%） | 351.7 px | 260.9 | 408.5 |
| 中位数 | 0/990（0.0%） | 351.7 px | 260.9 | 408.4 |

三种取值几乎一样差，说明**问题不在取哪个统计量**，而在"框的下沿"这个像素本身：

- 杆状目标（接触网柱、信号柱）在整幅画面里是一根竖线，框的下沿落到的位置是**它脚下的地面**，
  那里点云的深度是地面到相机的距离，不是目标到相机的距离；两者在远场能差几十米。
- 站台上的行人框下沿落到站台面，同理。

所以"2D 框 + 稀疏点云"这一对输入，信息量不足以给框内的目标定深度。要修必须做实例级点云分割
（把属于该目标的点从背景里分出来），或者用双目/深度网络，成本远高于本项目的剩余价值。

### 13.3 三轮方法都指向同一结论

| 轮次 | 方法 | 结果 |
|---|---|---|
| 1 | 框级晚融合（IoU 关联） | 融合 mAP50 0.6457 < 单 RGB 0.7002 |
| 2 | 标定/经验平面单应关联 | 残差 11–485 px，且"最优"解是带反射的畸形矩阵，不可用 |
| 3 | 激光雷达真深度关联 | 990 框 0 命中，残差 352 px |
| 4 | 帧级决策融合（完全绕开配准） | `fusion_or` 与 `rgb_only` 逐格相同：红外没补到任何一帧 RGB 漏掉的类别 |

四个独立角度，同一结论：**在 OSDaR23 这套采集配置下，红外在本项目可用的关联方式内没有带来增益。**
根因链也清楚：IR 视场只有 RGB 的 1/3（10.35°×7.77° vs 29.96°×19.73°）、安装高度差 1.4 m、
目标又多是细长杆状物 → 配准误差大于目标本身尺寸。

### 13.4 这一轮真正的收获

1. **点云→图像投影链路已验证可用**（`railintrude/lidar.py`），可给像素真实深度。这是检测之外
   第二条可写进材料的工程能力，也是替代"手工标定距离映射"的正路。
2. **把"融合失败"从猜想变成了四重否证**，并且每条都有可复现脚本和数字。
3. 明确了如果还要做融合，唯一剩下的路是**实例级点云分割**（成本另计），而不是继续调关联参数。
