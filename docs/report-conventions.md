# 报告约定：每个数字都要标出来源类型

用户要求（2026-10-26）：「以后复现论文内容并做消融实验，还要在报告我时给我标出」。
这份文件就是那条要求的执行细则。**写任何汇报、文档、Word、账本之前先读这一页。**

## 1. 四类标签（每个数字必须挂一个）

| 标签 | 定义 | 例子 |
|---|---|---|
| **【基线】** | 本仓库自带、可复现的参照物，不是论文方法 | 516 图 YOLOv8n（mAP50 0.7027）；COCO 零样本（mAP50 0.0000） |
| **【复现】** | 按某篇论文**原文的方法与设置**重跑，并注明论文编号（`refs/README.md` 的编号，如 B2、A1） | 复现 A2 的区域级分割头 |
| **【消融】** | 在【基线】或【复现】之上**只改一个变量**，其余全部固定 | A 轴：训练图 361 → 1359；C1 轴：5 类 → 4 类；D 轴：类路由 on/off |
| **【自研】** | 本仓库自己设计的工程链路，不对应任何论文方法 | lidar 点云反投影测距；INS 航向测速；TTC 四级报警 |

规则：

1. **【自研】不许写成【复现】**。哪怕思路来自论文，只要设置改了，就写「【复现】+ 改动清单」或直接标【消融】。
2. 每个数字后面跟**来源路径**：`docs/xxx.md` §N，或 `out/xxx/metrics.json`。没有路径的数字不许出现在汇报里。
3. 表格必须有一列 **「来源类型」**，写上面四个标签之一。
4. 【复现】必须多写一行 **「与原论文的差异」**：数据集、分辨率、epoch、类别数、指标口径（mAP50 vs mAP50-95 vs F1）任一项不同都要写。
5. **单次训练不称"提升"**。只有 ≥3 个种子的「均值 ± 极差」才可以说"提升"；否则写"单种子观测到 +0.0xx，落在历史抖动范围内"（本项目已实测抖动 0.019，见 `docs/yolo-version-compare.md`）。

## 3. 复现论文的标准流程（以后照做）

1. 从 `refs/README.md` 选一篇，记下编号与标题，在 `docs/readings/<编号>.md` 写「方法要点 / 我需要的改动 / 需要的数据」。
2. 先写 **最小可跑版本**，跑通后立刻记录：本仓库 mAP、论文 mAP、**差异项清单**。
3. 再在它上面做【消融】：一次只改一个变量，其余抄自己上一步的配置。
4. 写进文档时用第 1 节的标签与来源路径。

## 4. 汇报模板（给用户看的每一段）

每次汇报必须按 **三段式** 讲，顺序固定。三段中任何一段为空，要显式写「空：原因」，不许省略。

### ① 复现了什么（从哪篇论文）

```

复现的目标：<该方法/该表格/该超参>
论文原始读数：mAP50 = <x>（<数据集/协议>）
本仓库读数：mAP50 = <y>（<同一 val、同一 imgsz>）
差异项（deviation）：
  - <差在哪：数据集切分 / 类别定义 / 输入分辨率 / 训练轮数 / 增强>

```
