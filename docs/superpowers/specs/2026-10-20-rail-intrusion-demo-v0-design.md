# 车端侵限检测 V0 演示 · 设计说明

- 日期：2026-10-20
- 状态：待用户确认
- 上游：`轨道交通侵限检测-项目大纲.md`（给导师版）；本文件只覆盖**第一步 demo**的边界
- 后续：V1（OSDaR23 微调 + 可见光/红外双模态）另立 spec，本文件不涉及

---

## 1 一句话目标

把"一段列车前视视频"变成"一段带检测框、估计距离、TTC 和四级报警的视频 + 一张事件表"，
用一个**零训练的通用检测器**先把整条管线跑通，作为后续双模态融合与风险模型实验的骨架。

## 2 为什么先做 V0

- **检测器是可替换插槽**：V0 用 COCO 预训练模型（person / 车辆本来就在 COCO 的 80 类里，不需要训练）。
  V1 换成 OSDaR23 微调版 + 红外分支时，管线一行不改，只换 `Detector` 的实现。
- **风险层与检测器解耦**：距离 → TTC → 分级 → 滞回，这一层是创新点 C2 的雏形，先用它把
  "预警提前量""单位时间误报数"两个指标的统计口径跑通。
- **当前条件约束**：8 GB 笔记本显存、外网约 50 KB/s、GitHub 不可达。V0 不训练、不下载大数据集，
  1–2 天可交付可视化成果。

## 3 输入与输出

**输入**：任意前视视频（mp4 / webm）。
默认素材：`data/raw/platform-arrival-1080p.webm`
（Wikimedia Commons，莫斯科地铁 81-540.2 列车进"技术学院"站，1080p，57.3 s，39.9 MB）

**输出**（写在 `out/`）：

| 文件 | 内容 |
|---|---|
| `demo.mp4` | 1280×720，画框 + 距离 + TTC + 顶部报警条 + HUD |
| `events.csv` | 事件表：`frame,time_s,level,track_id,cls,distance_m,ttc_s` |

## 4 管线

```
视频帧 → 轨道 ROI 判定 → 检测 → IoU 跟踪 → 单目距离 → TTC → 分级(滞回) → 渲染/记录
```

### 4.1 轨道 ROI

归一化梯形多边形，4 个顶点写在配置里，默认覆盖画面下方约 55%。
**判定**：目标框**底边中点**落在多边形内 → 侵限候选。

理由：车端前视画面里轨道面是收敛梯形，比"取下半屏"更接近真实可用区域；
V1 把它换成轨道分割 mask 时，接口不变（`RoiPolygon.contains(x, y)` 换成 mask 查表）。

### 4.2 检测

`torchvision` 的 `fasterrcnn_mobilenet_v3_large_320_fpn`，COCO 预训练，CPU 推理。
只取 7 个"可侵限"类别：`person, bicycle, car, motorcycle, bus, truck, train`，`conf ≥ 0.5`。

**为什么不用 YOLO**：本机实测 GitHub 不可达、外网约 50 KB/s，ultralytics 的权重走 GitHub；
而 torchvision 的预训练权重走 `download.pytorch.org`，实测可达。检测器封成接口，
V1 换 YOLO / 双分支时不动管线。

### 4.3 跟踪

约 30 行的 **IoU 贪心匹配** + 轨迹老化（`max_age = 15` 帧）。
不用 ByteTrack：V0 不需要身份切换指标，IoU 足够为 TTC 提供短时序。

### 4.4 单目距离

地面平面假设 + 两点标定，反比模型：

```
d(y) = a / (y - y_h)
```

由两个标定点 `(y1,d1)`、`(y2,d2)` 闭式解出：

```
y_h = (d2*y2 - d1*y1) / (d2 - d1)
a   = d1 * (y1 - y_h)
```

默认标定：`y = 0.95H → 6 m`，`y = 0.62H → 50 m`（H 为帧高，y 用归一化值）。

> `ponytail:` 只对"接地点可见"的目标成立；站台高处的人（脚被遮挡）算出来会偏大。
> 演示够用，**评测必须用 LiDAR 真值**（OSDaR23 自带），升级路径是在 V1 用点云拟合真实标定曲线。

### 4.5 TTC 与四级报警

`TTC = d / v_self`（目标静止假设，`v_self` 默认 40 km/h，可配置）。

| 等级（内部/输出枚举） | 中文 | 条件 |
|---|---|---|
| `notice` | 注意 | TTC > 8 s |
| `alert` | 提示 | 5 s < TTC ≤ 8 s |
| `warn` | 警告 | 3 s < TTC ≤ 5 s |
| `emerg` | 紧急 | TTC ≤ 3 s |

内部、CSV、视频叠加一律用英文枚举（OpenCV 的 Hershey 字体画不了中文），
文档与答辩口语用中文。这个映射只写一次，别在两个地方各定义一遍。

**滞回**：升级当帧生效；降级需连续 **5 帧**低等级才生效（防闪烁）。

### 4.6 渲染与事件记录

- 框色随等级：`notice` 灰、`alert` 黄、`warn` 橙、`emerg` 红。
- 左上角 HUD：帧号、当前最高等级、最近目标距离、设定车速；顶部一条 24 px 报警色带。
- `events.csv` **只在等级发生变化时**写一行，首帧写一行。

## 5 验收标准

| 编号 | 标准 | 判定方式 |
|---|---|---|
| A1 | 给定视频能产出 `out/demo.mp4`，帧数与输入**可实际解码帧数**一致（±1），分辨率 1280×720。注：webm 容器元数据声明的帧数会大于可解码帧数（实测 1433 vs 1431），判据以逐帧解码计数为准 | 读回输出视频比对 |
| A2 | 出现 `person` 检测的帧占比 > 30% | 汇总统计 |
| A3 | `events.csv` 至少有一条 `warn` 或 `emerg` 事件 | 打开文件看 |
| A4 | 单元测试全绿（几何 / 风险 / 跟踪 / 管线），管线测试用 `FakeDetector`，不依赖模型权重 | `pytest -q` |
| A5 | 57 s 视频端到端在 10 分钟内跑完（CPU） | 记录耗时 |

## 6 明确不做（V0 边界）

- 不训练、不微调 —— V1
- 不做红外分支、不做融合消融 —— V1（C1）
- 不做 mAP / 漏检率评测 —— V1（需要 OSDaR23 标注与夜间子集）
- 不做制动 / 控制闭环 —— 永远不做（EN 50128/50129 的 SIL 门槛，AI 只报警）
- 不做 GUI，不做标注工具

## 7 风险与对策

| 风险 | 对策 |
|---|---|
| 夜间站台画面暗，检测召回低 | `conf` 与输入尺寸可调；A2 阈值只设 30%，不追求好看数字 |
| FasterRCNN 320 输入分辨率低，远处人漏检 | 远处目标本来就只落在 `notice` 级；距离拉近后可靠 |
| 外网慢导致权重下载失败 | 权重缓存到 `models/`；失败自动退回 `ssdlite320_mobilenet_v3_large` |
| 单目距离误差大 | 文档写清限制；演示只强调"距离趋势"与分级逻辑，不宣称测距精度 |
