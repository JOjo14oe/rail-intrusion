# V0 技术报告：车端侵限检测与分级预警（纯推理演示 + 微调实验）

版本：V0 / 日期：2026-10-20
工程目录：`rail-intrusion`

---

## 1. 这一版做了什么事

一个可运行的车端（驾驶室视角）侵限检测最小闭环：

视频 → 逐帧检测 → 轨道 ROI 过滤 → 多目标跟踪 → 距离估计 → TTC → 四级报警 → 带框视频 + 事件表

并在此之上做了一次**微调实验**（自动伪标注 → 训练 → 前后对照），结论是负面的，但负结果本身是这一版最有价值的部分（第 6 节）。

### 关键公式

- **单目距离（两点标定反比模型）**：$d(y) = \dfrac{a}{y - y_h}$。给定两组"像素纵坐标 → 真实距离"（默认 $y{=}0.95H \to 6\,\text{m}$、$y{=}0.62H \to 50\,\text{m}$），反解 $y_h = \dfrac{d_2 y_2 - d_1 y_1}{d_2 - d_1}$、$a = d_1 (y_1 - y_h)$。
- **TTC**：$TTC = d / v_{self}$，默认自车 40 km/h。
- **四级报警**：`notice`（>8 s）/ `alert`（≤8 s）/ `warn`（≤5 s）/ `emerg`（≤3 s）。
- **滞回**：等级升高当帧生效；降低需连续 5 帧确认，防抖动刷报警。
- **时序门控**：轨迹连续命中 ≥3 帧才允许升级报警，单帧误检只画框不报警。

### 为什么单目距离只是近似

只有像素纵坐标一个观测量，等价于假设"地面水平 + 相机姿态固定 + 目标底部接触地面"。目标腾空、坡道、相机俯仰变化都会带来误差。**它够用来做演示与相对趋势，不能用来做安全距离判定**；要量化误差必须以 LiDAR 或双目为真值。这一点在第 7 节局限里再次强调。

## 5. 结果二：微调实验（负结果）

用原权重对本视频做伪标注（2180 个框），切时间序训练/验证集，微调 yolov8n 后在同一验证集对照：

| 变体 | 数据 | 设置 | mAP50 | mAP50-95 | P | R |
|---|---|---|---|---|---|---|
| v3 解冻 | 245 目标帧 + 47 背景 | 60 epoch，freeze=0 | 0.6315 **(−0.358)** | 0.4839 (−0.364) | 0.9911 | 0.4652 |
| v4 冻结 | 同上 | 25 epoch，freeze=10，lr 0.002，mosaic=1 | 0.9882 (−0.0009) | 0.7499 (−0.098) | 0.7638 | 0.9915 |
| v5 冻结+无马赛克 | 245 目标帧 + **116 背景** | 25 epoch，freeze=10，lr 0.002，mosaic=0 | 0.9921 (+0.0002) | 0.7674 (−0.086) | 0.6378 **(−0.280)** | 1.0000 |

三个变体都在**第 1 epoch** 取得最好结果，随后早停。

**原因**：验证集标签由同一权重生成，学生初始化即位于最优点，损失在起点≈0，梯度只能把它推离最优点。所以"微调后更高"在数学上不可能；可训练部分（检测头）唯一能做的就是压低报警门槛——于是 recall 被推到 1.0，precision 腰斩。完整推导与复现命令见 `docs/finetune-experiment-report.md`。

## 6. 结果三：一个必须写进答辩的失效模式

微调后的权重在隧道段把"大片暗区 + 车头灯"识别成 `train`，给出覆盖画面 60% 的巨型框；框底边落在标定近端 → 距离 5.6 m → TTC 0.5 s → 直接 `emerg`。

| 模型 | 第 120 帧 | 第 149 帧 | 第 1079 帧 |
|---|---|---|---|
| 原权重 | 0 检测 | 0 检测 | 0 检测 |
| v4 | `train` 0.811 | 0 | `train` 0.974 |
| v5 | 0 | 0 | `train` **0.974**（框 (1,30,903,1053)） |

加背景帧 + 关马赛克把 3 帧压住 2 帧，最坏那帧仍是 0.974。**时序门控拦不住它**——该框连续存在十几帧，不是单帧抖动。

这个例子的价值：它说明"距离映射会把任何一个贴地的大框变成一个紧急报警"，也就是**检测误差会被几何放大成安全结论**。这正是后面要做融合与风险层的动机。

## 7. 局限（写进材料的"诚实边界"）

1. **单视频、单场景、单车型**：一条莫斯科地铁进站素材，25 fps，白天站台 + 隧道。所有结论不能外推到其他线路、天气、光照。
2. **无红外数据**：这一版的"双模态"只是设计，还没有实现；隧道/夜间失效（第 6 节）恰恰是红外该补的缺口。
3. **单目距离是透视近似**：见第 2 节，只能做演示与趋势，不能做安全判定。
4. **伪标签自举无法提升**：第 5 节的负结果，不是调参问题。
5. **未做真值评测**：没有人工标注，所有 mAP 都是相对同一教师的相对值，不是绝对性能。
6. **不做制动/控制闭环**：AI 只做检测/报警，安全动作交给独立 SIL 认证逻辑（EN 50128/50129）。这是刻意设定的范围边界。

## 8. 复现

```powershell
cd "rail-intrusion"

# 端到端演示（GPU）
python -m railintrude.demo --video data/raw/platform-arrival-1080p.webm --out out/full --device 0

# 数据集 / 训练 / 对照
python tools/build_dataset.py --video data/raw/platform-arrival-1080p.webm --out data/dataset_v4 --stride 3 --conf 0.35 --neg-stride 2 --device 0
python tools/train_experiment.py --data data/dataset_v4/dataset.yaml --epochs 25 --freeze 10 --lr0 0.002 --mosaic 0 --device 0 --name finetune-v5-nomosaic --out out/experiment_v5

# 测试
python -m pytest -q
```
