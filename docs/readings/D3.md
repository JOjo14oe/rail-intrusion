# D3 Rail-PillarNet（CMC 2024）复现规格

- 文献：`refs/2024_Rail-PillarNet-LiDAR-3D-FOD_CMC.pdf`，全文 `refs/extracted-text/2024_Rail-PillarNet-LiDAR-3D-FOD_CMC.txt`
- 出处：Computer Modeling in Engineering & Sciences（CMC），2024, vol.80, no.3, pp.3821–3840，开放获取
- 复现目的：这是我找到的**唯一一篇直接用 OSDaR23 的 LiDAR 做检测、且把数据切分/超参/每类 AP/消融表全写清楚的论文**，而 OSDaR23 我已全量拿到（43 个 zip，40 GB）。它同时符合伊老师课题组的产出模式（3D/2D 目标检测 + 轨道交通场景 + 明确的模块改进）。
- 来源类型：**【复现】**（判定见 `docs/report-conventions.md`）

## 1. 论文做了什么

Rail-PillarNet = PointPillars 基础上加三件东西：

| 模块 | 论文写法 | 消融代号 |
| --- | --- | --- |
| Point Attention（PA） | 在点维度上做注意力，聚合大目标（车、列车）的局部特征 | Model B |
| Channel Attention（CA） | 在通道维度做注意力，对小目标更有效 | Model C |
| 细化 backbone（残差结构 + 显式点编码） | 提升特征提取能力 | Model E / F |
| 迁移学习（TL） | 用 KITTI 预训练初始化 | Model G |

结构上仍是 pillar 范式：体素化 → 2D 骨干 → 检测头，因此**参数量只从 4.85M 涨到 5.49M**，推理 31.77 ms（TITAN RTX）。

## 5. 我方已声明的偏差（写进论文/汇报时必须带上）

1. **split 未知**：论文不给 train/val 列表，我按种子 0 随机 8:2 切，得 1069/267。单次切分波动可到 ±2–3 点 mAP（本项目在 2D 任务上实测过训练抖动 0.019 mAP50）。判定基线是否复现成功时，允许 ±3 点。
2. **帧数 1336 vs 1356**：差 20 帧（1.5%），来自"filtered and sifted"的细节不可知。另外我曾因为一个**零填充 bug** 只筛出 699 帧——OSDaR23 的 openlabel frame_id 写 `65`，而 lidar 文件名叫 `065_1631....pcd`，直接按字符串匹配会整段丢序列；现已用 `railintrude/kitti.py: frame_id_key` 归一，并留了回归测试 `tests/test_frame_id_key.py`。
3. **反射强度写 0**：`railintrude/lidar.py: read_pcd` 只返回 xyz，KITTI bin 的第 4 列填 0。论文用 4 维输入（xyz + 反射强度），这一条会压低复现上限，属于已知损失。
4. **硬件**：单张 RTX 4060 Laptop 8 GB，batch 2 可行，但 epoch 时间会是论文的数倍；不追求 31.77 ms 的时延数字。
5. **正文与 Table 2 不自洽**（见 4.1 注），以表为准。

## 8. 二读：方法细节与口径判断（2026-10-31 补）

第一版只记了"要复现什么"，这一节记"哪些地方不能照字面抄"。

### 8.1 点编码是 10 维，不是 PointPillars 的 9 维

`[x, y, z, r]` + 到 pillar 内**均值**的偏移 `[xc, yc, zc]` + 到 pillar **中心**的偏移 `[xp, yp, zp]`。
PointPillars 原版是 9 维（4 + 到中心 xy + pillar 内相对位置）。多出来的 1 维是 z 方向偏移——增量很小，属于常规增强。

### 8.2 PAPE 的实际结构：CBAM 搬进 pillar

```
Ap = σ(MLP(avgpool_points(P)) + MLP(maxpool_points(P)))    # P×N×1，每点权重
Ac = σ(MLP(avgpool_channels(P)) + MLP(maxpool_channels(P))) # P×1×C，每通道权重
Po = P + P·Ap + P·Ac                                        # 残差式加权
f  = maxpool(FC(Po))
```

判断：公式 (3) 与 (6) 形式完全同构，就是把 CBAM 的点/通道双路池化 + 共享 MLP + sigmoid 从 2D 特征图搬到 pillar 内部。不是新机制，是合理移植——**写论文时不能说"提出了一种新的注意力"，只能说"首次用于 rail LiDAR 的 pillar 编码"**。

**论文没交代、必须自己定的自由度**：`Ac` 的通道维 C 是那 10 维输入特征，还是 FC 之后的 64 维？若作用在 10 维上，权重维度太小、收益会很弱；从"对小目标有效"的说法反推，更像是作用在 FC 后。复现时两种都跑，作为一项目方 deviation 记录。

### 8.3 backbone 表里藏着一个 KITTI 配置

论文结构表写 pseudo-image **640×320×64**，而它的检测范围是 X[-30,354]、voxel 0.16 → 真实伪图应是 **2400×400**（这也与"最大 16000 个 pillar"自洽）。
结论：**那张表是从 KITTI 版（70 m × 80 m）直接搬来的**，不能当 OSDaR23 的实际尺寸用。表里的 stride 与通道数可用，尺寸必须重算。

### 8.4 头与损失

- SSD 单阶段，7 参数框 `(x,y,z,w,l,h,θ)`，3D IoU 匹配；回归：中心用差值、尺寸用 `log(w_gt/w)`、角度用 `sin(θ_gt−θ)`。
- focal loss **α=0.25, γ=2.0**；方向头用交叉熵（即二分类 bin，与 PointPillars 一致，公式 (11) 只写了 sin 部分是简化表述）。
- 总损失权重 **β=(2.0, 1.0, 0.2)**——原文 PointPillars 是 (1, 1, 0.2)，**位置损失权重被暗自翻倍**，这是一个未声明的改动。
- 笔误：Eq (9) 写成 `Δz = z_gt − z_h`，下标错。

### 8.5 迁移学习（TL）的真实含金量

KITTI 预训练 → 载入 OSDaR23 训练 → 形状不匹配的层跳过。
问题：KITTI 的 anchor 尺寸与这里的四类差得远（尤其"列车 63 m 长"完全在 KITTI 分布外），因此真正迁移过去的只是 backbone 的低级特征，检测头几乎等于重学。Model G 相对 F 的 +5.35/+4.50（车/人）里，有多少来自 KITTI 场景相似性、多少来自更好的初始化，论文没有拆开。**复现时这一项要单列，不能混进"方法改进"。**

### 8.6 论文数字的三条可信度折扣

1. **它没赢过 SECOND**：SECOND 58.91 > Rail-PillarNet 58.51，卖点是 31.77 ms vs 57.96 ms、5.49M vs 9.83M。材料里只能写"同等精度下更快更小"。
2. **每类 IoU 阈值不统一**：行人报的是 IoU **0.25** 的 AP（24.30）。我在 IoU 0.5 下复现，行人一定低于 24.30——**这不是复现失败**。判定基线时必须按"车/止挡/列车看 0.5、行人另算"分开比。
3. **单次训练、无种子、无区间**：+1.79%、+1.44% 这类差值可能落在噪声内（本项目在 2D 任务上实测同配置换种子差 0.019–0.04 mAP50）。所以消融方向要比，幅度不要照抄。

另外 +12.83 的总提升里，**列车一项贡献 +19.90**（39.07→58.97）——63 m 长的框最容易占便宜，平均值被大目标拉高，而论文的动机恰恰是"远距离小目标"。这是它最大的逻辑弱点，也是我方"更优解"可以下刀的地方。

### 8.7 执行路线的实际偏差（必须写进汇报）
